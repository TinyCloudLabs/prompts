## Fix first: behaviour bugs found by the audit

These are wrong instructions, not length. Each is small and should land before any trimming.

1. **Health Log profile contradiction.** `skills/tc-apps/TINY-APPS.md` L276 says meal commands "normally [use] the existing onboarding profile". Six lines in the same file (L25, L37, L39, L43, L71, L73), `SKILL.md` L14 and L41, and forward test TA18 say Health Log uses `agent-meal` only. Rewrite L276: "Meal commands use `agent-meal` as `<CATALOG_PROFILE>` (§3)."
2. **Owner guide promises a question the product forbids.** `skills/tc-apps/QUICKSTART.md` L89 tells owners the agent "asks whether you kept that app's records with an earlier version". `SKILL.md` L120 and `TINY-APPS.md` L19 forbid that question (TC-2431, forward test X). The TC-2431 regex misses this wording.
3. **Outcomes with no next step.** tc-publish §4 prints `MISMATCH (…)`, but nothing says not to deliver the link (L290-317). `REVEAL_FAILED` (L281, L361) and `SEND_FAILED` (L405) have no action at all. In tc-secrets §3d, `STARTING` → "run this block again in a few seconds" (L438) has no limit, so a CLI that never prints the link keeps the agent polling forever.
4. **A line too long for read tools.** `skills/tinycloud-feed/creating-a-post.md` L61 is 804 characters. Read tools cut at about 768, so its last instruction (`--yes` on a `local-owner-key` profile) never reaches the agent. The auditor's own read cut it.
5. **Silent truncation in legacy mode.** `kv list` in `LEGACY.md` L74, L137 and `LEGACY-SQL.md` L112, L114 has no `--all`, unlike `SKILL.md` L309 and `SQL.md` L105, L107. A large kind can come back incomplete.
6. **Pointers that miss plugin installs.** The `LEGACY.md` and `LEGACY-SQL.md` reads and `migrate.sh` (`SKILL.md` L118, L426; `LEGACY.md` L214-216) list two of the four install folders. They have no `${CLAUDE_SKILL_DIR}` and no curl fallback, so a plugin-installed agent can't reach them.
7. **Drifted copies in the SQL files.** `SQL.md` L90 and L159-160 tell the agent to check a session `"state"` and a "§1b" that exist only in `LEGACY-SQL.md`. `LEGACY.md` L210 still waits for an OpenKey code that the index sign-in no longer uses.

## The vendored skill: what is weak or doesn't fit us

The skill was vetted before vendoring. It has no network fetches, installers, scripts, hidden or zero-width characters, or instructions aimed at anything outside the document being written. The only non-ASCII characters are two `→`. The files were copied byte for byte.

- **Its description triggers only on skills and AGENTS.md/CLAUDE.md.** ("Use when creating or editing skills, or modifying AGENTS.md or CLAUDE.md.") It won't fire on its own for `setup/` guides, `standard/blocks.md`, `prompt.txt` or the forward-test runbooks, which are most of this repo's agent-read text. The AGENTS.md line in this PR covers that gap, so we don't fork the skill.
- **It has no review procedure and no done-condition.** It is all reference. The "review pass" and "done when you can no longer find duplication, sediment or no-ops" appear only on the aihero.dev page, not in the files. The AGENTS.md line supplies the done-condition: no no-op, duplication, cache or sediment in the changed lines.
- **"Settle it by running the document" names no method.** Our method is the forward tests. Without that link, an agent may cut a line a forward test pins because the line reads like a no-op. Several of them read that way: "Don't repeat the title", "Never a made-up or future time", the separate-terminal warning. The auditors kept these only because they checked the runbooks. A future rewrite pass must do the same.
- **Its negation advice clashes with our security guardrails.** "Prompt the positive", but our skills carry hard guardrails: never print a secret value, never put a share link in notes, never approve for the owner. The skill allows guardrails "you cannot phrase positively", but an agent told to "streamline" will cut them. Keep a guardrail only if it is pinned by a test or forward test, or if removing it would let a secret, link or grant leak.
- **Claude-specific mechanics.** `SKILL-MECHANICS.md` describes invocation through `disable-model-invocation`, a Claude Code frontmatter key. Codex uses `agents/openai.yaml` `policy.allow_implicit_invocation` instead, and other clients have no equivalent. All four of our product skills are model-invoked, so this doesn't affect us today. Under our AGENTS.md vendor rule, never make a product skill user-invoked using only the Claude key.
- **It assumes one reader.** Our QUICKSTART.md files and `setup/` guides are read by owners and agents both. The skill has no guidance on mixed audiences, and the audits found owner text inside agent files (feed SKILL.md L10) and agent rules inside owner files (tc-apps QUICKSTART L111). Rule of thumb: an agent-read file states rules for the agent, and an owner-facing file states what the owner sees.
